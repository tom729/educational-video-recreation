# 从选题到成片：可移植制作流程

适用于第一次接手的 Agent。具体美术、配音和验收标准见 [日常科普制作规则](daily-science-production.md)。本文件负责制作依赖、阶段交付和修订方式，不要求安装其他 Skill。

## 1. 明确本次交付边界

先从当前请求与项目文件判断：只讨论选题、只写脚本、只做开场样片、接着做下一段、做完整视频，还是修订已有成片。只做用户要求的阶段；用户已授权完整制作时，不自行增加逐段审批。

- 用户明确说“脚本确认后再做”：完成可审阅脚本与分镜，在此停下。
- 用户说“先做开场看看”：只制作开场样片、首帧封面和预览；其余可准备但不冒充成片。
- 用户说“继续下一段”：读取已批准的风格、上一段末状态与整片脚本，制作紧接的段落。
- 用户说“继续后面几段”：完成剩余授权段落；不是每段完成都再次询问。
- 用户仅评估话题：提供判断与具体切入，不自动消耗视频生成服务。

用项目内 `project.json` 或等效文档记录：选题、封面问题、语言、受众、画幅、留白、输出要求、当前阶段、已确认内容、下一段、版本与待核实问题。路径相对项目目录；不依赖聊天记忆保存状态。

## 2. 核对原理，写脚本和分镜

原创选题查官方资料、原始论文、工程文件；参考视频先实际读取。建立 `research.md`，每个重要结论记录：原文来源 URL、查阅日期、支持的事实、适用型号/条件、是否为设计目标、尚存疑点。搜索摘要只用于定位，关键机制需要原文支撑。

把一条视频限制在可闭合的核心问题内。脚本结构可采用“生活现象或工程矛盾 → 必要背景 → 原理分步 → 回答封面问题”，不强制统一段数。结尾内容在录音前写完整，不临时靠一句局限性判断结束。

用分镜表逐段记录：

| 字段 | 用途 |
|---|---|
| id | 稳定标识，修订不随便重排 |
| narration | 正式解说词，也是字幕文字真源 |
| pronunciation | 多音字、专有词、缩写与数字读法 |
| visual | 场景、部件、动作、画面短标注 |
| mechanism | 该段需要准确呈现的因果与连接关系 |
| transition_in / transition_out | 上一段如何进入、下一段如何离开 |
| source | 对应研究记录 |
| estimated_duration | 合成前估时；配音后以实测时间替换 |

复杂内容先判断能否删旁枝，再决定拆为几条；每条有独立封面、背景与结论。视频长度、分段数不固定为历史案例的值。

## 3. 锁定视觉结构与试制代表段

建立无品牌、辨识准确的主体；不要用精致装饰弥补错误结构。生成式图片可用于气氛、材质或静态概念，精确吊装、接头密封、电流路径、光路和守恒变换需要可控几何或可信素材。概念外观与真实产品结构分开标记。

优先做一个同时包含主体、局部放大和转场的代表段，检查字体、颜色、比例、留白与动作。用户已认可的风格应延续到后续段落，保留共同对象及配色参数。此试制步骤本身不构成额外审批要求。

日常科普在 1080×1920 下的安全内容框为：`x∈[108,972]，y∈[384,1728]`。字体笔画、描边、光晕、字幕及整个运动轨迹都计入；其他分辨率按百分比换算。首帧的标题、问题及主体完整显示在安全框内。

## 4. 配音先生成，时间轴后定稿

保留 `audio/raw/<id>` 原始合成文件；处理后的文件独立保存。记录语音服务、音色、语速/语气参数和文字版本，便于只重做有问题的一句。选择当前环境可用的中文 TTS，不写死服务商或音色 ID。

正式文本与合成输入分开。只有实际需要纠音时才建立 `tts_text` 与替代映射；字幕及词级标记恢复为正式用字。优先使用服务的音素功能。不要把合成输入中的“南”等替代字显示成“难”的正式字幕。

实际配音出来后，再生成 `timeline.json` 与字幕：

- 各段记录 `start`、原音时长、有效发声范围、保留头尾、显式段间停顿、`end`。
- 计算段间停顿时包括上一段尾部与下一段头部，不重复累计。
- 词级时间戳若不可用，可做语音对齐或按短句校正；估算时间需标明，不能宣称精准逐字对齐。
- 先保证完整字音，再决定淡出与停顿。用同一时间轴驱动字幕、镜头、转场、预览章节及帧数。
- 用户要求“更有精神”时调整重音、提问和结尾语气；不能仅增加音量或全片加速。

音频响度无指定标准时，可把语音约 −16 LUFS、真峰值不高于 −1 dBTP 作为处理起点；根据平台和素材调整，不能仅靠响度数值判断有感情。编码后重新测量，避免削波或尾部被 `-shortest` 截断。

## 5. 场景、预览与离线导出共用时间轴

选合适工具：二维信息与精确路径可用 SVG/Canvas；真实三维受力、转动、视差优先用 Blender，按 [Blender 制作流程](blender-production.md) 生成模型、剖面、拆解及镜头动画；已有实拍素材用剪辑流程。无论工具，尽量让 `renderFrame(t)` 或同等场景状态决定画面，而不是依靠实时定时器碰运气。随机粒子固定种子。

局部展开时，整体缩到一侧并保留位置提示；在同一对象上连续缩放、位移或剖切。旧标注退出后新标注出现，不用全屏交叉淡化把两个主体叠在一起。

预览是控制界面，视频是纯画面。默认暂停在真实首帧；加载、切片、拖进度、章节跳转、回到开头以及切换 Canvas 模式后均暂停。只有明确播放操作启动音画；循环与自动下一集默认关闭。音画共用一个时钟，跳转后重新同步。

离线逐帧导出，再封装配音，默认 H.264 / yuv420p / 30 fps / 1080×1920。有声视频建议 AAC。音频总长与视频末尾缓冲均纳入目标时长；不能为了满足预估秒数截断最后一句。首帧 PNG 从最终 MP4 提取，不以另画封面代替。

## 6. 验收成片，不只验收源码

运行附带的 `scripts/verify_video.py`。示例中的时长要替换为当前时间轴确定的值：

```bash
python3 /path/to/educational-video-recreation/scripts/verify_video.py \
  outputs/example/video-v1.mp4 --duration 72.5 \
  --cover outputs/example/cover.png --require-audio --scan-holds
```

脚本检查编码、尺寸、帧率、解码帧数、时长、音轨存在性及疑似静帧，不验证科学正确性、留白、尾音或情绪。

人工/视觉核对最终首帧、每个机制的中间状态、转场边界和结尾。检查整个运动范围的安全区；需要时采样或扫描全片。抽样通过不能声称每帧已经目视检查。

音频要对照原音检查每段尾字、呼吸衰减、段间间隔及编码后的最终音轨。可试听时核对读音和语气；用户要求安静或环境没有音频感知能力时，使用解码、波形、静音边界和文本比对，并在 `validation.md` 明确“未试听”。不得擅自调整系统音量或默认播放成片。

## 7. 修订与交付

只改需要改的内容，重要旧版与原音保留。改发音、停顿或尾音后重新测时，并同步字幕、镜头、章节、封面和导出；改画面时通常不需要重生成全部声音。拆片按因果链重写独立引子，不按秒数硬切。

建议项目结构（按实际需要增减）：

```text
outputs/project-name/
  project.json
  research.md
  script.md
  timeline.json
  audio/raw/
  audio/processed/
  assets/
  src/
  # 使用 Blender 时还交付建模脚本、参数和 scene.blend；纹理/缓存按需保留
  index.html
  releases/v1/
    video-v1.mp4
    cover.png
    captions.srt
    validation.md
```

交付视频、封面、字幕、正式解说稿、可编辑源码与可用预览，并说明实测时长、当前版本、改动和未完成的核查。源码中使用相对资源路径；记录实际依赖、字体来源、启动/渲染命令与素材授权。端口由运行环境选择，不写死旧项目端口；“localhost”链接仅用于当前机器，不能当作对外发布地址。

长期保存约定到项目文件或本 Skill 的来源目录。更新后再打包，不能只修改安装副本，导致迁移包漏掉最新规则。
